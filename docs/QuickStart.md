# USB Guardian Quick Start

## 1. Install The Server

On the management PC, open Command Prompt as Administrator and run:

```bat
Install-Server.bat
```

The script publishes the server, opens TCP port 5050, creates or updates the
Windows service, and generates an agent token. Keep that token available for
endpoint installation.

Verify the listener before continuing:

```powershell
Invoke-RestMethod http://127.0.0.1:5050/health
```

Continue only when it returns `status: healthy`.

Open the dashboard on the Server machine and change the default `admin` password
before performing remote administration. The first password change is local-only.
Use `http://127.0.0.1:5050` for this first connection.

## 2. Install Each Endpoint

Copy the repository or deployment bundle to the endpoint, open Command Prompt as
Administrator, and run:

```bat
Install-Agent.bat
```

Enter the full HTTP/HTTPS Server URL, or its bare IP/DNS name, and the token
generated by the Server installer. Source installation requires the .NET 8 SDK;
the self-contained Endpoint MSI does not. The script publishes the Agent and
Notifier, registers the LocalSystem Agent service, and configures the Notifier to
start for every user at logon. It now rejects an unreachable Server or an empty,
malformed Agent configuration instead of completing with a disconnected Agent.

## 3. Open The Dashboard

Run:

```bat
Start-Control.bat
```

Enter `http://SERVER-IP:5050` and the admin password, then click **Connect**.
Select an endpoint to manage removable devices, sectors, learn mode, groups,
timed unlocks, and event history.

If the dashboard cannot reach the Server, verify `/health` and port 5050 before
checking the password. If it connects but shows no machines, verify the Agent
service, `C:\ProgramData\USBGuardian\agent_config.json`, and agent token.

## 4. Validate Before Locking A Fleet

On one test endpoint:

1. Confirm the endpoint appears online.
2. Attach a USB drive and verify it appears as a managed device.
3. Lock the endpoint and verify only the drive is disabled.
4. Allow the drive, relock, and verify the keyboard and mouse remain usable.
5. Test a short timed unlock and confirm automatic relock.

Do not deploy Wi-Fi blocking until you have a wired or local recovery path.
